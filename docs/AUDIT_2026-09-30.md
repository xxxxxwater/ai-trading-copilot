# Optimization Audit & Upgrade Plan — 2026-09-30

Scope: `main` at `154fa0831cbbe71fbd8e30e2f28e893d583cd60f`.

## Objective

Upgrade AI Trading Copilot from a useful research prototype into a more trustworthy deterministic research runtime without expanding the live-execution boundary. The repository must remain research/read-only: no authenticated exchange credentials, no order placement, and no LLM-to-venue execution path.

## Audit findings

### P0 — deterministic correctness

1. **Declared stop-loss is not executed by the simulator.**
   `StrategyIR.risk.stopLossPct` and `takeProfitPct` are parsed but `runBacktest` only exits on the RSI exit rule or end-of-data. A result can therefore materially understate strategy downside relative to the strategy source.

2. **Signal and fill happen on the same candle close.**
   RSI is calculated from candle `i` close and a fill is also booked at candle `i` close. This assumes a zero-latency market-on-close fill after observing the closing price. The safer deterministic default is signal-at-close / fill-at-next-open.

3. **Flat RSI is incorrect.**
   When both average gain and average loss are zero, the current RSI implementation returns 100. Conventional RSI handling for a flat series is neutral (50).

4. **Historical data can include an unfinished Binance candle.**
   Binance klines include the currently open candle. Backtests should consume closed candles only.

5. **Market candles are trusted without structural validation.**
   Non-finite values, invalid OHLC relationships, duplicate/out-of-order timestamps, or malformed provider payloads can flow into metrics.

### P1 — runtime resilience and API integrity

1. **AI review failure discards valid deterministic analysis.**
   If the provider call fails while `OPENAI_API_KEY` is configured, `/api/analyze-strategy` currently returns an error instead of preserving parser/risk output and degrading to the deterministic review.

2. **API inputs are inconsistently bounded.**
   Strategy routes validate fields, but chat and market-snapshot have weaker request-shape validation. Large or malformed chat payloads should fail before provider work.

3. **Provider failures are reported as client errors.**
   Binance timeout/upstream failures should be distinguishable from invalid user input and should not be flattened into HTTP 400.

4. **Provider data provenance is incomplete.**
   Backtest results should report dataset start/end and closed-candle finality so evidence is reproducible and auditable.

5. **Streaming error text can expose low-level provider details.**
   User-facing stream failures should use a stable public message.

### P1 — production hardening

1. Add baseline response security headers.
2. Add a lightweight liveness/capability endpoint that does not pretend external dependencies are healthy.
3. Keep CI gates at lint + typecheck + tests + production build, and expand tests around deterministic execution semantics.

### P1 — documentation correctness

The current architecture diagram implies `/api/analyze-strategy` and `/api/backtest` persist runs to PostgreSQL. The schema exists, but those route write paths are not wired. Documentation must describe the persistence layer as prepared/not-yet-wired rather than as an active runtime guarantee.

### P2 — follow-on architecture

- AST-specific Python/Freqtrade/Pine adapters with explicit confidence/evidence spans.
- Event-driven fills, partial fills, funding, borrow, liquidation and venue-specific execution models.
- Walk-forward/OOS, Monte Carlo and parameter-sensitivity jobs.
- Auth/RBAC and durable run history before exposing paid AI endpoints publicly.
- Provider interface for Binance/Hyperliquid/IBKR/internal market data.
- Read-only portfolio/runtime adapters before any proposal-to-execution design.

## Acceptance gates

Every implementation commit must preserve the no-live-execution boundary. Final `main` should satisfy:

```bash
npm run lint
npm run typecheck
npm test
npm run build
```

Additional behavioral gates:

- A parsed stop-loss changes the simulated exit path when crossed.
- A signal observed at candle close cannot fill at that same close.
- Incomplete Binance candles are excluded from historical simulation.
- Invalid candle structures fail closed instead of producing metrics.
- AI-provider failure does not erase deterministic parser/risk evidence.
- Documentation does not claim persistence or execution paths that are not implemented.
